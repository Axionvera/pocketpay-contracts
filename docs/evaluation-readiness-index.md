# PocketPay Contracts Evaluation-Readiness Index

Use this page as the central starting point before requesting review or evaluation. The linked documents remain the source of truth for each requirement.

## Contributor workflow

1. **Payment-period expectations:** [Payment-Period Communication Policy](PAYMENT_POLICY.md) and [Payment-Period Conduct Guidance](payment-period-conduct.md).
2. **Testing standard:** [Test Naming Conventions and Coverage Guidance](testing.md) and [Invariant Test Checklist](invariant-test-checklist.md).
3. **Local checks and CI guidance:** [CONTRIBUTING — Build, format, and test](../CONTRIBUTING.md#build-format-and-test), the [Self-Review CI checklist](self-review-template.md#3-ci), and the [Test Reproduction Guide](reproducing-test-failures.md).
4. **Acceptance-criteria evidence:** [Acceptance Criteria Audit Template](ACCEPTANCE_CRITERIA_AUDIT.md) and [Traceability Table Guide](traceability-table.md).
5. **Self-assessment:** [Contract Evaluation-Readiness Checklist](evaluation-readiness-checklist.md), [Contributor Self-Review Template](self-review-template.md), and [Approval Readiness Checklist](approval-readiness-checklist.md).
6. **Reviewer evidence:** [Reviewer Evidence Checklist](REVIEWER_EVIDENCE_CHECKLIST.md) and [Contributor Security Checklist](security-checklist.md).

## Before requesting review

- Re-read the issue and map every acceptance criterion to concrete implementation, test, or documentation evidence.
- Follow the testing and security guidance that applies to the change.
- Complete the contributor self-review and the repository's required verification.
- Confirm the pull request has the evidence a reviewer needs.
- Use the payment-period communication guidance for any later evaluation-status follow-up.
